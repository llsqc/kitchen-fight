# 单人/多人模式场景分离方案

## 一、现状分析

### 1.1 当前模式架构

项目通过一个 `public static bool` 标志区分单人/多人模式：

| 入口 | `playMultiplayer` | 流程 |
|---|---|---|
| "Play Singleplayer" 按钮 | `false` | `StartHost()` → 直接加载 `GameScene` |
| "Play Multiplayer" 按钮 | `true` | `LobbyScene` → `CharacterSelectScene` → `GameScene` |

单人模式本质上是一个**只有 Host 自己的独立会话**（无远程客户端加入），多人模式是 **Host + 其他客户端加入**。两者永远不会出现在同一个会话中。

### 1.2 当前场景清单

```
Assets/Scenes/
├── MainMenuScene.unity
├── LoadingScene.unity
├── LobbyScene.unity
├── CharacterSelectScene.unity
└── GameScene.unity          ← 单人和多人共用
```

### 1.3 关键代码现状

**场景加载入口**（`KitchenGameMultiplayer.cs`，第 60-64 行）：

```csharp
private void Start() {
    if (!playMultiplayer) {
        // Singleplayer
        StartHost();
        Loader.LoadNetwork(Loader.Scene.GameScene);
    }
}
```

**场景枚举**（`Loader.cs`）：

```csharp
public enum Scene {
    MainMenuScene,
    GameScene,            // 单人多人共用
    LoadingScene,
    LobbyScene,
    CharacterSelectScene,
}
```

**玩家生成**（`KitchenGameManager.cs`，第 58-63 行）：

```csharp
private void SceneManager_OnLoadEventCompleted(string sceneName, LoadSceneMode loadSceneMode, ...) {
    foreach (ulong clientId in NetworkManager.Singleton.ConnectedClientsIds) {
        Transform playerTransform = Instantiate(playerPrefab);
        playerTransform.GetComponent<NetworkObject>().SpawnAsPlayerObject(clientId, true);
    }
}
```

**出生点**（`Player.cs`，第 34、81 行）：

```csharp
[SerializeField] private List<Vector3> spawnPositionList;
...
transform.position = spawnPositionList[KitchenGameMultiplayer.Instance.GetPlayerDataIndexFromClientId(OwnerClientId)];
```

出生位置是 Player Prefab 上硬编码的 `Vector3` 列表，按连接顺序分配，不支持按模式区分。

### 1.4 当前架构的天然隔离

| 维度 | 单人模式 | 多人模式 |
|---|---|---|
| 网络会话 | 独立 Host（仅自己） | 独立 Host + 远程客户端 |
| 场景 | `GameScene` | `GameScene` |
| 交互物体 | 场景内所有物体 | 场景内所有物体 |
| 玩家 | 仅自己 | 自己 + 其他人 |

**核心问题：** 单人和多人共用同一个 `GameScene`，如果想让两种模式使用不同的地图元素（灶台数量、柜台位置、出生点等），当前架构无法直接做到，因为场景文件是同一个。

## 二、方案对比

### 方案 A：同场景 + 不同出生点（仅改出生位置）

**思路：** 不复制场景，只在 `Player.cs` 里根据 `playMultiplayer` 选择不同的 `spawnPositionList`。

```csharp
// Player.cs 改动
transform.position = (KitchenGameMultiplayer.playMultiplayer ? multiplayerSpawnList : singleplayerSpawnList)
    [KitchenGameMultiplayer.Instance.GetPlayerDataIndexFromClientId(OwnerClientId)];
```

| 维度 | 评价 |
|---|---|
| 改动量 | 极小，1 个文件改几行 |
| 地图元素 | ❌ 无法改变场景内物体（灶台、柜台等位置和数量固定） |
| 适用场景 | 只想改出生位置，地图布局不需要变 |

**结论：** 不满足"不一样的地图元素"需求。仅列出作为对比。

### 方案 B：同场景 + NetworkHide 隔离（不可行）

**思路：** 单人和多人玩家在同一场地，用 `NetworkObject.NetworkHide()` 互相隐藏。

| 维度 | 评价 |
|---|---|
| 玩家互相不可见 | ✅ 技术可行 |
| 交互物体隔离 | ❌ 场景内灶台、柜台是共享的 NetworkObject，无法按模式隔离 |
| 游戏状态隔离 | ❌ `KitchenGameManager` 的倒计时、胜负判定是全场景共享的 |
| 改动量 | 巨大，需要重写交互系统、物品系统、游戏状态机 |

**结论：** 不可行。实际上单人和多人根本不会在同一会话中出现，不存在"互相看见"的问题。

### 方案 C：两个场景（推荐）

**思路：** 复制 `GameScene` 为独立的单人场景，单人模式加载新场景，多人模式继续用原场景。两个场景内的地图元素可以完全不同。

| 维度 | 评价 |
|---|---|
| 改动量 | 小，3-4 处代码 + 1 个场景文件 |
| 地图元素 | ✅ 两个场景可以放完全不同的灶台、柜台、出生点 |
| 侵入性 | 极低，不影响现有多人逻辑 |
| 后续维护 | 两套场景需要分别维护，但可以随时同步 |

**结论：** 最简单、最干净、最能满足需求的方案。

## 三、推荐方案：方案 C 详细设计

### 3.1 新增场景

复制 `GameScene.unity` → `GameSceneSingleplayer.unity`，在复制出的场景中调整：

- 灶台/柜台的位置和数量
- 出生点坐标
- 装饰物布局
- 任何你想为单人模式定制的地图元素

### 3.2 代码改动

#### 3.2.1 `Loader.cs` — 新增场景枚举

```csharp
public enum Scene {
    MainMenuScene,
    GameScene,
    GameSceneSingleplayer,    // 新增
    LoadingScene,
    LobbyScene,
    CharacterSelectScene,
}
```

#### 3.2.2 `KitchenGameMultiplayer.cs` — 单人分支加载新场景

```csharp
private void Start() {
    if (!playMultiplayer) {
        // Singleplayer
        StartHost();
        Loader.LoadNetwork(Loader.Scene.GameSceneSingleplayer);  // 改为单人场景
    }
}
```

#### 3.2.3 `Build Settings` — 注册新场景

在 Unity Editor → File → Build Settings 中添加 `GameSceneSingleplayer.unity`。

### 3.3 数据流

```
单人模式:
  MainMenuUI → playMultiplayer = false → KitchenGameMultiplayer.Start()
      → StartHost()
      → Loader.LoadNetwork(Scene.GameSceneSingleplayer)
      → KitchenGameManager.SceneManager_OnLoadEventCompleted
      → Instantiate(playerPrefab) → SpawnAsPlayerObject()
      → Player.OnNetworkSpawn() → 读取单人场景的出生点

多人模式 (不变):
  MainMenuUI → playMultiplayer = true → LobbyScene → CharacterSelectScene
      → KitchenGameMultiplayer.StartHost/StartClient()
      → Loader.LoadNetwork(Scene.GameScene)
      → KitchenGameManager.SceneManager_OnLoadEventCompleted
      → Instantiate(playerPrefab) → SpawnAsPlayerObject()
      → Player.OnNetworkSpawn() → 读取多人场景的出生点
```

### 3.4 注意事项

1. **`KitchenGameManager` 是场景级对象**：两个场景各放一个 `KitchenGameManager`，其 `playerPrefab` 引用可以在 Inspector 中分别配置不同的 Player Prefab（如果需要不同的出生点列表），也可以共用同一个 Prefab。
2. **出生点隔离**：如果两个场景共用同一个 Player Prefab，`spawnPositionList` 就是同一份。如果需要不同出生点，可以：
   - 方式一：两个场景各放一个 `Player Prefab` 变体（Prefab Variant），各自配置不同的 `spawnPositionList`。
   - 方式二：在场景中放置带 Tag 的空 GameObject 作为出生点，`Player.OnNetworkSpawn` 时按 Tag 查找（替代硬编码列表）。
3. **`NetworkConfig.Scenes` 配置**：Netcode for GameObjects 要求场景在 Build Settings 中注册后才能通过 `SceneManager.LoadScene` 加载，新场景必须加入 Build Settings。

## 四、实现步骤

### Step 1: 复制场景

- 在 Unity Editor 中复制 `Assets/Scenes/GameScene.unity`
- 重命名为 `GameSceneSingleplayer.unity`

### Step 2: 修改 Loader.cs

- `Scene` 枚举新增 `GameSceneSingleplayer`

### Step 3: 修改 KitchenGameMultiplayer.cs

- 单人分支的 `LoadNetwork` 参数从 `GameScene` 改为 `GameSceneSingleplayer`

### Step 4: 注册到 Build Settings

- Unity Editor → File → Build Settings → Add Open Scenes → 添加 `GameSceneSingleplayer`

### Step 5: 编辑单人场景

- 在 `GameSceneSingleplayer.unity` 中调整地图元素、出生点等

### Step 6: 编译验证 + Play Mode 测试

- 编译检查无错误
- 单人模式：从主菜单进入 → 加载 `GameSceneSingleplayer` → 玩家在正确位置出生 → 地图元素正确
- 多人模式：从主菜单进入 → 正常走 Lobby → 加载 `GameScene` → 行为与改动前一致
