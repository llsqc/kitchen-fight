# 单人/多人模式场景分离方案

## 一、结论

采用两个独立游戏场景：

- `GameSceneSingleplayer`：单人模式专用
- `GameScene`：多人模式专用，保留现有名称和流程

该方案适合两种模式在厨房布局、柜台数量、出生点、碰撞体、灯光或装饰等方面存在明显差异的情况。它对现有多人流程侵入较小，也比在同一场景中维护大量模式判断更直观。

需要特别注意：玩家出生坐标目前保存在共享的 `Player.prefab` 中。仅复制 `GameScene` 不会得到独立出生点，因此本方案同时将出生点改为场景级配置。

---

## 二、当前实际架构

### 2.1 模式标志

项目通过 `KitchenGameMultiplayer.playMultiplayer` 区分模式：

| 入口 | `playMultiplayer` | 实际流程 |
|---|---:|---|
| Play Singleplayer | `false` | `MainMenuScene` → `LoadingScene` → `LobbyScene` → 启动 Host → `GameScene` |
| Play Multiplayer | `true` | `MainMenuScene` → `LoadingScene` → `LobbyScene` → `CharacterSelectScene` → `GameScene` |

单人按钮当前也会先加载 `LobbyScene`。进入该场景后，`KitchenGameMultiplayer.Start()` 检测到单人模式，自动启动一个只有本机玩家的 Host，然后加载游戏场景。

单人和多人不会处于同一个网络会话，因此无需使用 `NetworkHide()` 让两种模式相互隔离。

### 2.2 当前场景

```text
Assets/Scenes/
├── MainMenuScene.unity
├── LoadingScene.unity
├── LobbyScene.unity
├── CharacterSelectScene.unity
└── GameScene.unity          # 当前由单人和多人共用
```

### 2.3 当前加载入口

单人模式由 `KitchenGameMultiplayer.Start()` 启动：

```csharp
private void Start() {
    if (!playMultiplayer) {
        StartHost();
        Loader.LoadNetwork(Loader.Scene.GameScene);
    }
}
```

多人模式在所有玩家完成角色选择后，由 `CharacterSelectReady` 加载 `GameScene`。这条多人加载路径不需要修改。

### 2.4 当前玩家出生方式

`KitchenGameManager` 在网络场景加载完成后生成玩家：

```csharp
Transform playerTransform = Instantiate(playerPrefab);
playerTransform.GetComponent<NetworkObject>()
    .SpawnAsPlayerObject(clientId, true);
```

随后 `Player.OnNetworkSpawn()` 从 `Player.prefab` 上的共享列表读取出生坐标：

```csharp
transform.position = spawnPositionList[
    KitchenGameMultiplayer.Instance
        .GetPlayerDataIndexFromClientId(OwnerClientId)
];
```

因此，复制场景只能隔离地图对象，不能自动隔离出生点。

## 三、最终设计

### 3.1 场景职责

```text
GameSceneSingleplayer
├── 单人厨房布局
├── 单人出生点
├── 单人专属场景对象
└── 共用 GameplayCore

GameScene
├── 多人厨房布局
├── 4 个多人出生点
├── 多人专属场景对象
└── 共用 GameplayCore
```

两个场景可以分别调整：

- 柜台、灶台、切菜台、交付台的位置和数量
- 玩家出生位置与朝向
- 地面、墙体和碰撞体
- 摄像机位置和活动范围
- 灯光、装饰和模式专属对象

公共的管理器、UI 和不随地图变化的对象应尽量做成 Prefab，由两个场景共同引用，避免后续修复只更新其中一个场景。

### 3.2 场景枚举

在 `Loader.Scene` 中加入单人场景：

```csharp
public enum Scene {
    MainMenuScene,
    GameScene,
    GameSceneSingleplayer,
    LoadingScene,
    LobbyScene,
    CharacterSelectScene,
}
```

当前 `Loader` 使用枚举名的 `ToString()` 作为场景名，所以场景文件必须准确命名为：

```text
GameSceneSingleplayer.unity
```

### 3.3 单人场景加载

仅修改 `KitchenGameMultiplayer.Start()` 中的单人分支：

```csharp
private void Start() {
    if (!playMultiplayer) {
        StartHost();
        Loader.LoadNetwork(Loader.Scene.GameSceneSingleplayer);
    }
}
```

多人模式仍由 `CharacterSelectReady` 加载 `Loader.Scene.GameScene`，不需要增加模式判断。

### 3.4 场景级出生点

推荐在两个游戏场景的 `KitchenGameManager` 下建立出生点对象：

```text
KitchenGameManager
└── PlayerSpawnPoints
    ├── SpawnPoint_0
    ├── SpawnPoint_1
    ├── SpawnPoint_2
    └── SpawnPoint_3
```

- 单人场景至少配置 `SpawnPoint_0`
- 多人场景配置 4 个出生点
- 出生点顺序继续对应玩家数据索引

在 `KitchenGameManager` 中序列化场景出生点：

```csharp
[SerializeField] private Transform playerPrefab;
[SerializeField] private Transform[] playerSpawnPoints;
```

生成玩家时先取得当前场景的出生点，再生成并 Spawn：

```csharp
private void SceneManager_OnLoadEventCompleted(
    string sceneName,
    LoadSceneMode loadSceneMode,
    List<ulong> clientsCompleted,
    List<ulong> clientsTimedOut) {

    foreach (ulong clientId in NetworkManager.Singleton.ConnectedClientsIds) {
        int playerIndex = KitchenGameMultiplayer.Instance
            .GetPlayerDataIndexFromClientId(clientId);

        Transform spawnPoint = playerSpawnPoints[playerIndex];
        Transform playerTransform = Instantiate(
            playerPrefab,
            spawnPoint.position,
            spawnPoint.rotation);

        playerTransform.GetComponent<NetworkObject>()
            .SpawnAsPlayerObject(clientId, true);
    }
}
```

同时删除 `Player` 中的 `spawnPositionList` 字段以及 `OnNetworkSpawn()` 内覆盖位置的代码，防止它把场景出生位置重新改回 Prefab 中的旧坐标。

这种做法只维护一个 Player Prefab，不需要创建和注册额外的 NGO Network Prefab Variant。

应在生成前校验出生点数组长度，避免配置遗漏导致越界。至少需要保证：

```csharp
playerIndex >= 0 && playerIndex < playerSpawnPoints.Length
```

### 3.5 Build Settings 与 NGO

将以下场景加入 Unity Build Settings 并保持启用：

```text
Assets/Scenes/GameSceneSingleplayer.unity
```

项目的 NGO `EnableSceneManagement` 已开启。当前版本不需要维护额外的 `NetworkConfig.Scenes` 列表；新场景进入 Build Settings，并能通过名称加载即可。

## 四、运行数据流

### 4.1 单人模式

```text
MainMenuUI
→ playMultiplayer = false
→ LoadingScene
→ LobbyScene
→ KitchenGameMultiplayer.Start()
→ StartHost()
→ Loader.LoadNetwork(GameSceneSingleplayer)
→ KitchenGameManager 读取单人出生点
→ 生成本机玩家
```

`LobbyScene` 是当前持久化网络管理对象的承载场景。单人模式会自动离开它，通常不会停留给玩家操作。

### 4.2 多人模式

```text
MainMenuUI
→ playMultiplayer = true
→ LoadingScene
→ LobbyScene
→ Host / Client 建立连接
→ CharacterSelectScene
→ 所有玩家 Ready
→ Loader.LoadNetwork(GameScene)
→ KitchenGameManager 读取多人出生点
→ 服务端生成所有玩家
```

---

## 五、实施步骤

1. 在 Unity Editor 中复制 `Assets/Scenes/GameScene.unity`。
2. 将副本命名为 `GameSceneSingleplayer.unity`。
3. 把新场景加入 Build Settings。
4. 在 `Loader.Scene` 中新增 `GameSceneSingleplayer`。
5. 将单人分支的目标场景改为 `GameSceneSingleplayer`。
6. 在两个游戏场景中建立并配置各自的出生点。
7. 修改 `KitchenGameManager`，从场景出生点生成玩家。
8. 删除 `Player.prefab` 上的硬编码出生坐标列表及对应赋值代码。
9. 在单人场景中调整地图布局和专属对象。
10. 将两场景共用的管理器和 UI 尽量整理成共享 Prefab。

## 六、涉及文件

| 文件 | 操作 | 说明 |
|---|---|---|
| `Assets/Scenes/GameSceneSingleplayer.unity` | 新增 | 单人专用场景 |
| `Assets/Scenes/GameScene.unity` | 修改 | 配置多人出生点 |
| `Assets/Scripts/Loader.cs` | 修改 | 增加单人场景枚举 |
| `Assets/Scripts/KitchenGameMultiplayer.cs` | 修改 | 单人分支加载新场景 |
| `Assets/Scripts/KitchenGameManager.cs` | 修改 | 使用场景级出生点生成玩家 |
| `Assets/Scripts/Player.cs` | 修改 | 移除 Prefab 硬编码出生位置逻辑 |
| `Assets/Prefabs/Player.prefab` | 修改 | 移除 `spawnPositionList` 序列化数据 |
| `ProjectSettings/EditorBuildSettings.asset` | 修改 | 注册新场景 |

`CharacterSelectReady.cs` 不需要修改，继续负责多人模式加载 `GameScene`。

## 七、验证清单

### 单人模式

- 从主菜单点击单人模式后进入 `GameSceneSingleplayer`
- 只生成一个玩家
- 玩家在单人出生点的位置和朝向生成
- 单人地图的柜台、碰撞体和摄像机正确
- 单人卡牌、计分、暂停和结束流程正常

### 多人模式

- Host 能正常创建并进入角色选择
- Client 能正常加入
- 所有玩家 Ready 后进入 `GameScene`
- 每个玩家在对应的多人出生点生成
- 场景内 NetworkObject 在 Host 和 Client 上一致
- 多人卡牌、队伍、计分和断线处理没有回归

### 重复进入

- 单人退出到主菜单后可以再次进入单人模式
- 多人退出到主菜单后可以重新创建或加入游戏
- 单人和多人交替进入时，加载的目标场景和出生点均正确

---

## 八、后续维护原则

- 地图布局和模式专属对象由各自场景维护。
- 通用玩法逻辑继续保留在共享脚本和 Prefab 中。
- 不创建仅为修改出生点而存在的 Player Prefab Variant。
- 新增场景级 NetworkObject 后，同时在 Host 和 Client 构建中验证场景同步。
- 修改公共 UI、管理器或游戏规则时，应检查两个游戏场景的引用是否仍然一致。
