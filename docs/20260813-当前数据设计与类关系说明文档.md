# 20260813-当前数据设计与类关系说明文档

## 一、整体概览

用一句话概括当前数据系统的运作方式：

> 策划在 Inspector 里创建 `SabotageItemSO` 资产（.asset 文件）配置每张卡牌的属性，这些资产放进 `SabotageItemListSO` 列表里。代码运行时通过**整数索引**（0、1、2、3…）从列表中取出对应的 SO，再用 SO 里的数据驱动 UI 显示和网络同步。

---

## 二、数据是怎么存储的

### 2.1 第一层：单个卡牌数据 — `SabotageItemSO`

**文件位置：** `Assets/Scripts/ScriptableObjects/SabotageItemSO.cs`

这是一个 `ScriptableObject`，简单说就是**一个可以在 Unity Inspector 里配置的数据模板**。策划不用写代码，只需要右键创建资产文件，然后在面板上填字段。

**它存了什么：**

```
 itemName      → "Stun"          道具名称（显示在卡牌上）
 effectType    → Stun            效果类型（4选1：眩晕/反向/锁定/净化）
 rarity        → Rare            稀有度（3选1：普通/稀有/史诗）
 targetType    → Player          目标类型（3选1：玩家/台面/自己）
 duration      → 2               持续时间（秒）
 icon          → Sprite          图标图片（可空）
```

**枚举也定义在同一个文件里：**

```
 EffectType:  Stun | ReverseControls | LockCounter | CleanWipe
 Rarity:      Common | Rare | Epic
 TargetType:  Player | Counter | Self
```

**实际存储位置：** 每张卡牌是一个 `.asset` 文件，存在 `Assets/ScriptableObjects/` 目录下。

### 2.2 第二层：卡牌列表 — `SabotageItemListSO`

**文件位置：** `Assets/Scripts/ScriptableObjects/SabotageItemListSO.cs`

也是一个 `ScriptableObject`，作用是把所有 `SabotageItemSO` 装进一个 `List` 里，并提供**索引查找**方法。

**它存了什么：**

```
 sabotageItemList → List<SabotageItemSO>    所有卡牌的列表
```

**两个关键方法：**

| 方法 | 作用 | 例子 |
|---|---|---|
| `GetFromIndex(int index)` | 输入索引，返回 SO | `GetFromIndex(0)` → 返回 Stun 卡牌 |
| `GetIndex(SabotageItemSO)` | 输入 SO，返回索引 | `GetIndex(stunItem)` → 返回 0 |

**实际存储位置：** `Assets/ScriptableObjects/SabotageItemList.asset`

当前列表里有 4 张卡牌：

| 索引 | itemName | effectType | rarity | targetType | duration |
|---|---|---|---|---|---|
| 0 | Stun | Stun | Rare | Player | 2 |
| 1 | Reverse | ReverseControls | Rare | Player | 8 |
| 2 | Lock | LockCounter | Common | Counter | 15 |
| 3 | CleanWipe | CleanWipe | Common | Self | 0 |

### 2.3 第三层：运行时快照 — `CardInfo`

**文件位置：** `Assets/Scripts/UI/CardInfo.cs`

这是一个 `struct`（结构体），**不是 ScriptableObject**，不存文件。它是运行时的"快照"——当外部代码想查询某张卡牌的信息时，EffectCardUI 把自己的数据打包成 CardInfo 交出去。

```csharp
public struct CardInfo {
    public int cardId;           // 卡牌运行时唯一编号（自增 1,2,3...）
    public int itemIndex;        // 在 SO 列表中的索引（0,1,2,3）
    public string name;          // 名称
    public string description;   // 描述
    public EffectType effectType;// 效果类型
    public Rarity rarity;        // 稀有度
    public TargetType targetType;// 目标类型
}
```

**为什么需要它？** 因为外部代码（比如其他系统）不应该直接访问 EffectCardUI 内部的 UI 组件和 SO 引用。CardInfo 是一个干净的、只读的数据副本，给了最小权限。

### 3.2 数据流转的完整路径

以"测试按钮添加一张卡牌"为例，数据从头到尾走一遍：

**第 1 步：点击按钮**
```
TogglePanelUI.Awake() 里绑定 testAddCardButton.onClick
玩家点击 → 执行 PickRandomItemIndex()
```

**第 2 步：随机选一个索引**
```
PickRandomItemIndex()
  → 先随机选稀有度（60% Common, 30% Rare, 10% Epic）
  → 在 sabotageItemListSO.sabotageItemList 里找匹配稀有度的
  → 返回索引，比如 0（Stun）
```

**第 3 步：用索引取出 SO 数据**
```
TogglePanelUI.AddCard(itemIndex=0)
  → sabotageItemListSO.GetFromIndex(0)
  → 返回 SabotageItemSO（Stun 那张卡牌的完整数据）
```

**第 4 步：把数据灌进 UI**
```
EffectCardUI.SetCardData(id=1, itemIndex=0, itemSO=Stun)
  → nameText.text = "Stun"
  → descriptionText.text = "对目标玩家眩晕 2秒"  (自动生成)
  → iconImage.sprite = itemSO.icon
  → backgroundImage.color = 蓝色（Rare 稀有度颜色）
  → CardId = 1, ItemIndex = 0, TargetType = Player
```

**第 5 步：玩家拖拽卡牌消除**
```
OnEndDrag → 判断向上超过 100px → 触发 OnCardDismissed 回调
  → TogglePanelUI.HandleCardDismissed(card)
    → sabotageItemListSO.GetFromIndex(card.ItemIndex=0) → 得到 SO
    → item.targetType == Player → 获取鼠标世界坐标
    → Player.UseCardServerRpc(itemIndex=0, aimPosition, counterRef)
```

**第 6 步：服务器执行效果**
```
Player.UseCardServerRpc(itemIndex=0, ...)
  → KitchenGameMultiplayer.GetSabotageItemFromIndex(0) → 得到 SO
  → ExecuteItemEffect(itemSO, aimPosition, counterRef, myTeamId)
    → itemSO.targetType == Player
    → Physics.OverlapSphere(aimPosition, 1.5f, Players)
    → 对每个命中的对手：PlayerEffectHost.ApplyEffect(Stun, 2, myTeamId)
```

**第 7 步：效果生效（网络同步）**
```
PlayerEffectHost.ApplyEffect(EffectType.Stun, duration=2, sourceTeamId)
  → 服务端设置 stunTimer.Value = 2f（NetworkVariable，自动同步到所有客户端）
  → 所有客户端的 stunTimer 值同步更新
  → PlayerEffectVisual 每帧读取 stunTimer > 0 → 显示眩晕星星动画
  → Player.Update() 每帧检查 IsStunned() → 阻止移动和交互
  → 2 秒后 stunTimer 自然减到 0 → 效果结束
```

## 四、网络同步的关键设计

### 4.1 为什么用整数索引而不是直接传 SO

在 Unity Netcode 中，**不能直接通过网络传输 ScriptableObject 引用**。SO 是 Unity 编辑器侧的概念，运行时它只是内存中的一个对象引用，不同客户端之间无法直接共享。

**解决方案：整数索引**

```
传输方：  itemIndex = 0（一个 int，4 字节）
接收方：  通过自己本地的 sabotageItemListSO.GetFromIndex(0) 找到同一个 SO
```

这要求**所有客户端的 SabotageItemListSO 里卡牌的排列顺序必须一致**。因为是在同一个 .asset 文件上引用的，所以天然一致。

### 4.2 NetworkVariable 计时器

效果持续时间用 `NetworkVariable<float>` 实现：

```
服务端设置：  stunTimer.Value = 2f
                ↓ Netcode 自动同步
所有客户端：  stunTimer.Value 变为 2f
                ↓ 每帧 Update
服务端递减：  stunTimer.Value -= Time.deltaTime
                ↓ 自动同步
所有客户端：  看到计时器递减
```

- 服务端是**唯一权威**：只有服务端能写 `Value`
- 客户端是**只读消费者**：读 `Value` 来驱动 UI 和逻辑
- `PlayerEffectHost` 和 `CounterEffectHost` 上的所有计时器都是这个模式

### 4.3 卡牌发牌的网路流程

```
服务端决定发牌
  ↓ player.AddCardClientRpc(itemIndex)
ClientRpc 触发（所有客户端收到）
  ↓ Player.OnCardAdded?.Invoke(itemIndex)
TogglePanelUI.Player_OnCardAdded(itemIndex)
  ↓ AddCard(itemIndex)
  ↓ sabotageItemListSO.GetFromIndex(itemIndex) → SO
  ↓ EffectCardUI.SetCardData → 填充 UI
```

注意：发牌走 `ClientRpc`（服务端→客户端），使用卡牌走 `ServerRpc`（客户端→服务端）。

## 五、各类的职责总结

| 类 | 类型 | 职责 | 持有的关键数据 |
|---|---|---|---|
| `SabotageItemSO` | ScriptableObject | 定义单张卡牌的静态属性 | name, effectType, rarity, targetType, duration, icon |
| `SabotageItemListSO` | ScriptableObject | 存储卡牌列表，提供索引↔SO 转换 | `List<SabotageItemSO>` |
| `CardInfo` | struct | 运行时卡牌信息的只读快照 | cardId, itemIndex, name, description, effectType, rarity, targetType |
| `EffectCardUI` | MonoBehaviour | 卡牌的 UI 表现（显示、悬浮、拖拽、消除） | CardId, ItemIndex, itemSO(缓存), TargetType |
| `TogglePanelUI` | MonoBehaviour | 卡牌面板管理（开关、发牌、回收、使用） | sabotageItemListSO 引用, nextCardId, cardContainer |
| `Player` | NetworkBehaviour | 卡牌使用的网络入口 | UseCardServerRpc, AddCardClientRpc, OnCardAdded 事件 |
| `PlayerEffectHost` | NetworkBehaviour | 玩家身上的效果计时器（服务端权威） | stunTimer, reverseTimer, recentVictimTimer, cleanWipeFlash |
| `CounterEffectHost` | NetworkBehaviour | 台面上的效果计时器（服务端权威） | lockTimer |
| `IEffectHost` | interface | 效果宿主的统一接口 | ApplyEffect, GetVictimState, ClearEffect, GetEffectRemaining |
| `KitchenGameMultiplayer` | NetworkBehaviour | 全局网络管理，持有 SO 列表引用 | sabotageItemListSO, GetSabotageItemFromIndex() |
| `SabotageSystem` | NetworkBehaviour | 落后补偿发牌 | 调用 player.AddCardClientRpc() |

## 六、当前设计的局限性

1. **命名不匹配**：`SabotageItemSO`（破坏道具）这个名字不适合即将加入的正面效果卡牌

2. **缺少效果强度**：没有 `magnitude` 字段，无法表达"1.5 倍速度"或"2 倍得分"

3. **缺少游戏模式区分**：没有 `gameMode` 字段，无法区分单人/多人卡牌

4. **缺少描述文本**：`SabotageItemSO` 没有 `description` 字段，描述靠 `EffectCardUI.GenerateDescription()` 硬编码生成，不灵活

5. **缺少占位色**：没有 `placeholderColor`，图标为空时只能用一个固定的黄色

这些问题在 `20260813-卡牌内容与效果重设计文档.md` 中已给出了改造方案（新建 `CardSO` 替代 `SabotageItemSO`）。
