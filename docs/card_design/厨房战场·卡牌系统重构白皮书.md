# 厨房战场·卡牌系统重构白皮书

> 从"破坏道具"到"策略卡牌"——一次彻底的数据、效果、网络三层重构

---

## 一、为什么必须重写

### 1.1 当前系统的症状

翻开 `SabotageItemSO.cs`，所有问题都源于一个文件：

```csharp
public enum EffectType {
    Stun, ReverseControls, LockCounter, CleanWipe,
}
```

这个枚举同时承担了三个职责：

| 职责 | 例子 | 问题 |
|---|---|---|
| 效果分类标签 | UI 上显示什么图标 | 加正面效果后枚举膨胀 |
| 执行逻辑分支 | `switch (effectType)` | 每加一个效果就要改 `ExecuteItemEffect` |
| 网络同步标识 | 通过索引传到服务端 | 枚举变动导致索引错位 |

更严重的是，`SabotageItemSO` 这个名字本身就带着"破坏道具"的基因——它无法优雅地容纳"加速移动"这种正面效果。

### 1.2 重写目标

| 目标 | 现状 | 重写后 |
|---|---|---|
| 支持正面效果 | 不支持 | 单人模式全是 Buff |
| 支持反制效果 | 不支持 | 多人模式有 Shield / Reflect |
| 效果强度可变 | 无 magnitude 字段 | 同一效果不同稀有度配不同数值 |
| 区分游戏模式 | 无 gameMode 字段 | Single / Multiplayer 分池 |
| 卡牌描述灵活 | 硬编码生成 | SO 自带 description，缺省时自动生成 |

## 二、数据层重构：从 SabotageItemSO 到 CardSO

### 2.1 新的枚举体系

```
GameMode        游戏模式      Single | Multiplayer
CardCategory    卡牌类别      Buff | Debuff | Counter
EffectType      效果类型      （见下文完整列表）
Rarity          稀有度        Common | Rare | Epic
TargetType      目标类型      Self | Player | Counter | Teammate
```

### 2.2 完整效果类型表

```
EffectType
├── 单人·Buff
│   ├── MoveSpeedUp          移动速度提升
│   ├── InteractionSpeedUp   交互速度提升
│   ├── DoubleScore          双倍得分
│   ├── ExtraTime            延长时间（即时）
│   ├── InstantComplete      瞬间完成（即时）
│   └── SelfClean             清除自身负面（即时）
│
├── 多人·Debuff（保留原有）
│   ├── Stun                 眩晕
│   ├── ReverseControls      反向操作
│   └── LockCounter          锁定台面
│
└── 多人·Counter（新增反制）
    ├── Shield                护盾：免疫下一次 Debuff
    └── Reflect               反弹：将下一次 Debuff 反弹给攻击者
```

### 2.3 CardSO 定义

```csharp
[CreateAssetMenu(fileName = "Card", menuName = "KitchenFight/Card")]
public class CardSO : ScriptableObject {
    // ── 身份信息 ──
    public string cardName;
    [TextArea] public string description;
    public Sprite icon;
    public Color placeholderColor = Color.white;

    // ── 分类标签 ──
    public GameMode gameMode;
    public CardCategory cardCategory;
    public Rarity rarity;

    // ── 执行参数 ──
    public EffectType effectType;
    public TargetType targetType;
    public float duration;      // 持续时间（秒），0 = 即时效果
    public float magnitude;     // 效果强度（1.5 = 1.5倍，2 = 翻倍，15 = 延长15秒）
}
```

### 2.4 CardListSO 定义

```csharp
[CreateAssetMenu(fileName = "CardList", menuName = "KitchenFight/CardList")]
public class CardListSO : ScriptableObject {
    public List<CardSO> cardList;

    public CardSO GetFromIndex(int index);
    public int GetIndex(CardSO card);

    // 按模式筛选卡牌池（发牌时用）
    public List<CardSO> GetCardsByMode(GameMode mode);

    // 按模式 + 类别筛选（更精细的卡池控制）
    public List<CardSO> GetCardsByModeAndCategory(GameMode mode, CardCategory category);
}
```

### 2.5 网络同步不变

仍然用整数索引。`KitchenGameMultiplayer` 持有 `CardListSO` 引用，通过 `GetFromIndex(int)` 转换。所有客户端的列表顺序一致（同一个 .asset 文件），天然同步。

## 三、效果执行架构

### 3.1 三段分流

当前的 `ExecuteItemEffect` 是一个巨型 switch。重写后按 `duration` 和 `cardCategory` 分流：

```
UseCardServerRpc(itemIndex, aimPosition, counterRef, sourceClientId)
  │
  ├── duration > 0（持续型）
  │     │
  │     ├── Buff → 对自己 ApplyEffect(type, duration, magnitude, ...)
  │     ├── Debuff → 定位目标 → 对目标 ApplyEffect(type, duration, magnitude, sourceClientId)
  │     └── Counter → 对自己设置防御计时器
  │
  └── duration == 0（即时型）
        │
        ├── ExtraTime → KitchenGameManager.AddGameTime(magnitude)
        ├── InstantComplete → 完成当前台面烹饪
        └── SelfClean → ClearAllNegativeEffects()
```

### 3.2 ApplyEffect 签名扩展

```csharp
// 旧签名
void ApplyEffect(EffectType type, float duration, int sourceTeamId)

// 新签名
void ApplyEffect(
    EffectType type,
    float duration,
    float magnitude,       // 新增：效果强度
    ulong sourceClientId    // 新增：攻击者 ID（反弹用）
)
```

## 四、PlayerEffectHost 重构

### 4.1 当前状态

```
PlayerEffectHost
├── stunTimer          负面
├── reverseTimer       负面
├── recentVictimTimer  被动减半保护
└── cleanWipeFlash     净化闪光
```

### 4.2 重构后

```
PlayerEffectHost
│
├── 负面效果计时器（可被拦截/反弹）
│   ├── stunTimer
│   └── reverseTimer
│
├── 正面效果计时器（Buff，不可被拦截）
│   ├── moveSpeedTimer + moveSpeedMagnitude
│   ├── interactionSpeedTimer + interactionSpeedMagnitude
│   └── doubleScoreTimer + doubleScoreMagnitude
│
├── 防御状态计时器（Counter）
│   ├── shieldTimer + shieldCharges    ← 护盾，拦截 Debuff
│   └── reflectTimer + reflectCharges ← 反弹，反弹 Debuff 给攻击者
│
└── 辅助状态（保留）
    ├── recentVictimTimer              ← 被动减半保护（保留）
    └── cleanWipeFlash                 ← 净化闪光视觉
```

### 4.3 ApplyEffect 入口逻辑（拦截链）

这是重写最核心的逻辑：

```
ApplyEffect(type, duration, magnitude, sourceClientId):
  │
  ├── 如果是 Buff（正面效果）:
  │     直接设置对应计时器，不做任何拦截
  │
  └── 如果是 Debuff（负面效果）:
        │
        ├── shieldTimer > 0 ?
        │     是 → 消耗 1 次护盾，return（效果被吞掉）
        │
        ├── reflectTimer > 0 ?
        │     是 → 消耗 1 次反弹，对 sourceClientId 施加同样效果，return
        │
        ├── recentVictimTimer > 0 ?
        │     是 → duration *= 0.5（保留现有减半保护）
        │
        └── 正常设置计时器
```

## 五、反制系统详解

### 5.1 净化（SelfClean）—— 事后补救

**场景：** 你被眩晕了，动不了，打出净化卡 → 立即解除。

**机制：**
- `ClearAllNegativeEffects()` — 把 stunTimer / reverseTimer 归零
- 已有代码，不需要改动
- 即时效果，无持续时间

### 5.2 护盾（Shield）—— 事前预防

**场景：** 你预判对手要干扰你，提前打护盾 → 下一个 Debuff 被完全吞掉。

**机制：**
- 新增 `shieldTimer`（NetworkVariable\<float\>）+ `shieldCharges`（NetworkVariable\<int\>）
- 打出护盾卡时：`shieldTimer = duration`，`shieldCharges = 1`（或 Epic = 2）
- 收到 Debuff 时：`shieldCharges > 0` → 消耗 1 次，效果不生效
- 护盾到期或次数用完自动消失

**与现有减半保护的区别：**

| 对比 | 减半保护 (recentVictimTimer) | 护盾 (Shield) |
|---|---|---|
| 触发方式 | 被动，被打后自动触发 | 主动，打牌触发 |
| 效果 | 持续时间减半 | 完全免疫 |
| 持续 | 10 秒 | 卡牌配置的 duration |
| 策略性 | 低（自动的） | 高（玩家选择时机） |

### 5.3 反弹（Reflect）—— 以牙还牙

**场景：** 对手对你丢眩晕，你有反弹 → 眩晕反弹到对手身上，你不受影响。

**机制：**
- 新增 `reflectTimer`（NetworkVariable\<float\>）+ `reflectCharges`（NetworkVariable\<int\>）
- 打出反弹卡时：`reflectTimer = duration`，`reflectCharges = 1`
- 收到 Debuff 时：`reflectCharges > 0` → 消耗 1 次
  - 找到 `sourceClientId` 对应的 Player
  - 对该 Player 调用 `ApplyEffect`（绕过拦截链，直接生效）
  - 自己不受影响

**难点与解决：**
- `ApplyEffect` 当前只接收 `sourceTeamId`，不知道具体是谁攻击的
- 扩展签名增加 `sourceClientId`
- `Player.UseCardServerRpc` 调用时传入自己的 `OwnerClientId`

## 六、稀有度设计

### 6.1 发牌概率（已有）

```
Common  60%
Rare    30%
Epic    10%
```

### 6.2 效果强度梯度（新增）

同一个 EffectType，不同稀有度配不同的 duration 或 magnitude。这意味着同一个效果会有 3 张卡牌（Common/Rare/Epic 各一张）。

**示例 — 加速移动：**

| 稀有度 | magnitude | duration |
|---|---|---|
| Common | 1.3 | 8s |
| Rare | 1.5 | 10s |
| Epic | 1.8 | 12s |

**示例 — 护盾：**

| 稀有度 | charges | duration |
|---|---|---|
| Common | 1 次 | 5s |
| Rare | 1 次 | 8s |
| Epic | 2 次 | 8s |

这只是数据配置，不需要代码改动——策划在 `.asset` 文件里填不同的数值即可。

## 九、迁移路线图

### Phase 1：数据结构迁移（行为不变）

**目标：** 用 CardSO 替换 SabotageItemSO，代码跑通但不加新效果。

1. 创建 `CardSO.cs` + `CardListSO.cs`（含新枚举）
2. 将现有 4 张多人 Debuff 卡牌迁移为 CardSO .asset 文件
3. 更新 `EffectCardUI`、`TogglePanelUI`、`Player`、`KitchenGameMultiplayer` 中的引用
4. 编译 + Play Mode 验证：行为与之前完全一致

### Phase 2：单人模式 Buff 效果

**目标：** 实现单人模式的 6 种正面效果。

1. `PlayerEffectHost` 新增 moveSpeedTimer / interactionSpeedTimer / doubleScoreTimer
2. `Player.HandleMovement` 接入速度 Buff
3. `CuttingCounter` 接入交互速度 Buff
4. `StoveCounter` 接入交互速度 Buff
5. `DeliveryManager` 接入双倍得分 Buff
6. `KitchenGameManager` 新增 `AddGameTime`
7. `Player.UseCardServerRpc` 处理即时效果
8. 创建 6 张单人卡牌 .asset 文件
9. 编译 + Play Mode 验证

### Phase 3：反制系统

**目标：** 实现护盾和反弹。

1. `PlayerEffectHost` 新增 shieldTimer / reflectTimer + charges
2. `ApplyEffect` 签名扩展 `magnitude` + `sourceClientId`
3. 实现 ApplyEffect 拦截链
4. `Player.UseCardServerRpc` 调用时传入 `OwnerClientId`
5. 创建 Shield / Reflect 卡牌 .asset 文件
6. 编译 + Play Mode 验证

### Phase 4：多人模式 Buff 卡牌

**目标：** 多人模式中可以对自己或队友施放正面效果。

1. 新增 `TargetType.Teammate`
2. 目标选择逻辑：瞄准队友施放 Buff
3. CrosshairUI 适配：瞄准队友时显示友方颜色
4. 编译 + Play Mode 验证
