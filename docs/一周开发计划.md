# KitchenFight 一周开发计划

- **日期**：2026-08-11
- **周期**：2026-08-11 ~ 2026-08-17（一周）
- **团队**：3 人（A / B / C）
- **本周重点**：修复已知缺陷 + 配置数据驱动化（SO 改造）
- **关联文档**：[游戏简介](./游戏简介.md) | [多人对战技术方案分析](./multiplayer-tech-analysis.md)

---

## 一、本周目标

基于 [技术方案分析](./multiplayer-tech-analysis.md) 中识别的问题，本周集中完成：

1. **修复阻塞发布的问题**（P0）— 安全校验、项目配置
2. **修复影响体验的问题**（P1）— 性能、错误提示
3. **配置数据驱动化**（SO 改造）— 让策划无需改代码即可调平衡

### 不做什么

- ❌ Phase 2 新道具开发（留到下周）
- ❌ 重连 / Host 迁移（工作量过大，单独排期）
- ❌ 服务端移动校验（反作弊改造，后续迭代）
- ❌ AI 填充 / 观战模式（长期规划）

---

## 二、人员分工

| 成员 | 方向 | 职责概述 |
|------|------|---------|
| **A** | 网络与配置 | 安全校验修复、项目配置修正、Lobby 错误提示 |
| **B** | 数据驱动改造 | 5 个新 SO 的创建与代码替换 |
| **C** | 性能与工程 | 性能优化、运行时对象创建修复、回归测试 |

### 依赖关系

```
A：独立工作，无依赖
B：独立工作，无依赖（SO 创建 → 代码替换 → 编译验证）
C：部分依赖 B（B 完成 SO 替换后 C 验证编译通过）
```

> B 和 C 有轻度交叉：B 完成 SO 改造后，C 负责验证和性能回归。A 完全独立。
